# Oracle Object Support Matrix

Scope: Oracle-to-Oracle FULL migration through `core/connectors/oracle/`.
Classification is based on the connector implementation, unit tests and recorded local-to-local migration results. The accepted local environment is Oracle AI Database 26ai Free using `config/oracle_local_to_local.yaml` (`SOURCE_OWNER` → `TARGET_OWNER`).

## Classification keys

| Class | Meaning |
|---|---|
| Supported | Implemented for the stated scope. |
| Partial | Implemented with restrictions on object type, dependency, configuration or state. |
| Unsupported | Not implemented or explicitly rejected in Oracle FULL. |
| Outside FULL | Provisioned separately; not a migration operation. |

| Validation | Meaning |
|---|---|
| Local → Local | Verified live for the documented fixture or earlier local audit, not every variant. |
| Code / unit | Implementation or unit-test evidence exists; specific live acceptance is not established. |
| Not verified | No sufficient live evidence for this case. |
| — | Not applicable or unsupported. |

Oracle may report an ordinary descending index as `FUNCTION-BASED NORMAL`, using a hidden `SYS_NC...` key and the original quoted column expression. The connector accepts the verified native DESC form and the intrinsic `SYS_OP_DESCEND` representation, not arbitrary function-based expressions.

## Users, roles and permissions

Permission migration is opt-in (`oracle_permission_migration.enabled: true`). The SOURCE inventory is owner-grant-driven, not a PDB-wide copy of accounts. A configured TARGET permission executor performs approved principal and role operations; TARGET owner grants on its own objects.

| Object | Support | Validation | Evidence / Notes |
|---|---|---|---|
| Application users | Partial | Local → Local | Two locked users created; passwords/hashes not copied. Existing account authentication/state preserved. |
| Local non-authenticated roles | Partial | Local → Local | Two roles; configured approval and executor authority required. |
| Role memberships | Supported within policy | Local → Local | Three memberships verified; required ADMIN OPTION checked. |
| Object-level SELECT, INSERT, UPDATE, DELETE | Partial | Local → Local | Ten direct/role object grants verified. |
| Column-level INSERT, UPDATE, REFERENCES | Partial | Local → Local (UPDATE) | One UPDATE grant on `PATIENTS.EMAIL`; other allowed classes not separately live-proven here. |
| System privilege CREATE SESSION | Partial | Local → Local | Two grants; explicit approval and direct executor ADMIN OPTION required. |
| Conditional executor provisioning | Supported | Local → Local | APPLY added CREATE USER, CREATE ROLE and CREATE SESSION WITH ADMIN OPTION when required. |
| Permission reconciliation | Supported within policy | Code / unit; local grants verified | `DMT_PERMISSION_PROVENANCE` tracks managed permissions; independent grants are not blindly removed. Untracked conflicts can block. |
| Grant/admin options from SOURCE, PUBLIC grants, unsupported role states, common/Oracle-maintained principals, other system privileges | Unsupported | — | Fail closed; no blanket DBA or ANY privilege elevation. |
| Oracle security policies / row-level security | Unsupported | — | No supported Oracle policy migration path claimed. |

Normal FULL migrates newly discovered supported grants when authority is already available. PLAN/APPLY is for account/authority setup, not a routine requirement per grant. See Document 01 and Document 04 for procedures.
